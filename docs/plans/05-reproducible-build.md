# 05 — Fully Reproducible hermes-stack Build

**Goal:** capture EVERYTHING done across this build so the entire stack —
the `aitools-*` Docker services AND the Hermes orb VM — is reproducible
from scratch with scripts in this repo. No reliance on the existing
`hermes`/`hermes-agent` VMs.

**Deliverables (all in `hermes-stack/`):**

```
hermes-stack/
  secrets.env.example        # ALL required secrets (gitignored real: secrets.env)
  justfile                   # one-command orchestration (up/down/build/status)
  build-stack.sh             # brings up aitools-backends + aitools-services in order
  build-hermes.sh            # provisions the Hermes orb VM from scratch
  aitools-backends/          # (exists) compose + pg-init
  aitools-services/          # (exists) compose + litellm + honcho config + honcho-src(gitignored)
  hermes-vm/
    systemd/hermes-dashboard.service
    systemd/hermes-gateway.service
    systemd/hermes-logtail.service
    bin/hermes-logtail.sh
    config/honcho.json.tmpl    # baseUrl + peer config (no secrets)
    config/config.yaml.model.tmpl  # the model: block (provider=custom, litellm)
  README.md                  # top-level: full from-scratch procedure + gotchas
  docs/plans/                # (exists) all phase plans incl. this one
```

## Secrets model

`secrets.env.example` lists every secret; real values in gitignored
`secrets.env`. Build scripts source `secrets.env`. Keys:
```
OPENROUTER_API_KEY=
VOYAGE_API_KEY=
TELEGRAM_BOT_TOKEN=
TELEGRAM_ALLOWED_USERS=
TELEGRAM_HOME_CHANNEL=
LITELLM_MASTER_KEY=          # generated if blank
# DB + virtual keys are generated by the scripts, not user-supplied
```
`build-*.sh` derive/rotate `POSTGRES_SUPERPASS`, `HONCHO_DB_PASSWORD`,
`LITELLM_DB_PASSWORD` (→ aitools-backends/.env + aitools-services/.env) and
generate LiteLLM virtual keys (→ aitools-services/keys.generated.env).
`.gitignore` already excludes `**/.env`, `**/keys.generated.env`,
`**/*.bak*`, `aitools-services/honcho-src/`; add `secrets.env`.

## build-stack.sh (Docker side) — exact sequence

1. `docker network create aitools-net 2>/dev/null || true`
2. Generate `aitools-backends/.env` (super/honcho/litellm pw via `openssl rand -hex 16`).
3. `cd aitools-backends && docker compose --env-file .env up -d` → wait pg+redis healthy.
4. Propagate `HONCHO_DB_PASSWORD`/`LITELLM_DB_PASSWORD` into `aitools-services/.env`;
   add `LITELLM_MASTER_KEY` (from secrets.env or `sk-$(openssl rand -hex 24)`),
   `OPENROUTER_API_KEY`, `VOYAGE_API_KEY` (from secrets.env).
5. `git clone https://github.com/plastic-labs/honcho aitools-services/honcho-src`
   then `git -C aitools-services/honcho-src checkout 8fcbb54 && rm -rf .git`
   (pinned commit — reproducibility).
6. `cd aitools-services && docker compose --env-file .env up -d aitools-litellm`
   → wait healthy (litellm-database auto-runs prisma migrations).
7. Generate virtual keys via `POST /key/generate` (alias honcho + hermes),
   write `aitools-services/keys.generated.env`; append `HONCHO_VIRTUAL_KEY`
   to `aitools-services/.env`. Expand the hermes key model-allowlist
   (`/key/update`) to include `chatgpt/*` + glm/grok.
8. Honcho fresh-DB init — **must use the venv, NOT `uv run`** (uv rebuilds
   the project in-image and fails):
   `docker compose --env-file .env run --rm --entrypoint /app/.venv/bin/python
   aitools-honcho-api scripts/configure_embeddings.py --yes` is run AFTER an
   alembic upgrade. Concretely: `up -d aitools-honcho-api aitools-honcho-deriver`
   (entrypoint runs alembic → schema at hardcoded 1536) → then the venv
   `configure_embeddings.py --yes` (alters to 1024) → recreate honcho so the
   boot `embedding_validator` passes (1024==1024).
9. Verify: pg18 `SELECT version()`; honcho/litellm roles login; honcho
   `documents`/`message_embeddings` are `vector(1024)`; e2e ingest→search→
   dialectic; LiteLLM spend logs grow.

## build-hermes.sh (orb VM) — exact sequence

Args: `[machine-name]` (default `hermes`). Refuses to touch `hermes-agent`.

1. `orb create ubuntu <machine>` (Ubuntu 25.10 era).
2. In the machine: `sudo apt-get update && sudo apt-get install -y xz-utils`
   (**REQUIRED** — Hermes installer extracts Node `.tar.xz`; minimal Ubuntu
   lacks `xz-utils`; without it the installer fails).
3. Install Hermes: `curl -fsSL <hermes install.sh> | bash`; then
   `hermes setup` non-interactive or seed `~/.hermes/.env` from secrets.env
   (API keys, TELEGRAM_*).
4. Write `~/.hermes/honcho.json` from `hermes-vm/config/honcho.json.tmpl`
   (`baseUrl=http://aitools-honcho-api.orb.local:8000`, peerName=joe,
   aiPeer=hermes, workspace=hermes, pinPeerName=true, sessionStrategy
   per-session).
5. Patch `~/.hermes/config.yaml` `model:` block from
   `hermes-vm/config/config.yaml.model.tmpl`: `provider: custom`,
   `base_url: http://aitools-litellm.aitools-services.orb.local:4000/v1`,
   `api_key: <HERMES_VIRTUAL_KEY from keys.generated.env>`,
   `default: chatgpt/gpt-5.5`.
6. Do **NOT** install native honcho/postgres (Honcho is Dockerized). Only
   install services: `hermes-dashboard.service`, `hermes-gateway.service`
   (`sudo hermes gateway install --system --run-as-user joe` OR the captured
   unit), `hermes-logtail.service` + `/usr/local/bin/hermes-logtail.sh`
   (mirrors `~/.hermes/logs/{gateway,errors}.log` → `/dev/console` so logs
   appear in OrbStack's machine Logs tab — that tab IS the console, not
   journald; agent.log excluded as DEBUG-spammy).
7. `sudo systemctl daemon-reload && sudo systemctl enable --now
   hermes-dashboard hermes-gateway hermes-logtail`.
8. Verify: `hermes -z "ping"` returns content (Hermes→LiteLLM→chatgpt/gpt-5.5,
   it streams so the LiteLLM non-streaming-chatgpt bug doesn't bite);
   `hermes honcho status` connects to Dockerized Honcho;
   `orb logs <machine> | grep hermes-` shows forwarded logs.

## Gotchas to encode in README (hard-won this build)

1. **xz-utils**: Hermes installer needs it on minimal Ubuntu (upstream bug;
   PR https://github.com/NousResearch/hermes-agent/pull/11278).
2. **Honcho config = `config.toml` + env**; precedence `env > .env >
   config.toml`. Never commit secrets in config.toml — DB URI + API key
   come from compose env; config.toml carries placeholders only.
3. **Voyage embeddings via LiteLLM**: keep `embedding.dimensions_mode =
   "never"` (Voyage 400s on `dimensions`); LiteLLM translates anyway. PG
   vector cols must be 1024 via `configure_embeddings.py` (venv, not uv run).
4. **PG major rebuild wipes the LiteLLM DB → virtual keys vanish** →
   regenerate keys + update Honcho's key after any pg volume reset.
5. **`chatgpt/*` via LiteLLM**: non-streaming completions fail (known
   LiteLLM bug; streaming OK). Hermes streams → fine. **Honcho must NOT use
   chatgpt/\*** (deriver/summary/dream/dialectic-tool-steps are non-stream)
   — keep Honcho on glm/grok/voyage.
6. **OrbStack machine Logs tab = the console (`/dev/console`)**, not
   journald. Forward logs there (root) to surface them in the UI.
7. **`hermes-agent` is the frozen original — never modified.** New work in
   the clone/`hermes`. (Reproducible builds start from a fresh `orb create`,
   not the clone, so this only matters for the existing machines.)
8. Pin everything: litellm image digest, honcho source commit, pg/redis
   versions; deliberate bumps via commits.

## Acceptance
- Fresh `./build-stack.sh && ./build-hermes.sh fresh-test` (or via justfile)
  on a clean OrbStack produces a working stack: Hermes chats via LiteLLM,
  Honcho memory works, logs visible in OrbStack Logs tab — with only
  `secrets.env` provided.
- No secrets tracked in git (`git ls-files | grep -E '\.env$|keys.generated|
  secrets.env|honcho-src/'` → none).
- README documents the procedure + all 8 gotchas.
