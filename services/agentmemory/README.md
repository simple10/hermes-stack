# agentmemory

Third-party memory backend. File-based state on its own volume (no pg
dep — `SERVICE_REQUIRES=litellm` only). When `HERMES_MEMORY=agentmemory`,
Hermes loads the `@agentmemory/mcp` shim and points at
`agentmemory.<project>.orb.local:3111`. Deeper 6-hook provider integration
is a manual copy of `integrations/hermes` into `~/.hermes/plugins/agentmemory`.

## Levers

```
AGENTMEMORY_MODEL=${STACK_LLM_MODEL}
AGENTMEMORY_EMBEDDING_MODEL=${STACK_LLM_EMBEDDING_MODEL}
AGENTMEMORY_EXPOSE_VIEWER=1
```

`AGENTMEMORY_SECRET` is generated by `just setup` (stored at the top of
`.stack/.env`, not in the service block — it's a secret).

## ⚠ AGENTMEMORY_EXPOSE_VIEWER security note

The admin web UI at `:3113` is **UNAUTHENTICATED**. With
`AGENTMEMORY_EXPOSE_VIEWER=1` (default) it's exposed at
`agentmemory.<project>.orb.local:3113` — fine since orb DNS is the trust
boundary, but anyone with stack network access (other containers / the VM)
can read+write your memories.

Set `AGENTMEMORY_EXPOSE_VIEWER=0` to keep the viewer 127.0.0.1-only inside
the container (unreachable via orb DNS).
